加分项

- 参与过开源项目或技术社区

我们能提供
- 和国内最优秀的 AI 产品团队一起工作
- 扁平化管理，没有层层汇报
- 薪资 open，上不封顶
- 一日三餐 + 健身房 + 无限零食

## 三、解析决策注释

标注 LLM 在解析过程中做出的关键判断，说明"为什么这么解析"。

### 3.1 去噪 —— 什么被过滤了

| 原文段落 | 处理 | 理由 |
|---------|------|------|
| "我们是谁…国内用户规模最大的大模型 C 端产品之一" | **过滤**——非需求信息 | 属于公司介绍/雇主品牌，不影响岗位画像 |
| "团队由算法、工程、产品、设计多角色组成" | **过滤**——非需求信息 | 团队背景，非岗位要求 |
| "我们能提供…一日三餐 + 健身房 + 无限零食" | **过滤**——非需求信息 | 福利说明，非岗位要求 |

### 3.2 翻译 —— "黑话 → 人话"

| JD 原文 | 解析后的实际含义 | 处理方式 |
|---------|----------------|---------|
| "皮实，能承担快节奏的迭代压力" | 加班较多，对情绪稳定性有要求 | **保留原文措辞存入 content**。黑话表在 Prompt 中帮助 LLM 正确归类为 must_have / 软素质，但不改写原文 |
| "扁平化管理，没有层层汇报" | 公司规模小/中等，决策链短 | **过滤**——属于公司文化描述，非对候选人的要求。（但如果公司评估模块启用，会提取到 `CompanyBrief` 里） |
| "薪资 open，上不封顶" | 薪资偏绩效导向，底薪可能不高 | **过滤**——薪资描述，非岗位要求 |

### 3.3 归类 —— must_have vs nice_to_have

| 原文 | 归类 | 判断依据 |
|------|------|---------|
| "理解大模型基本概念…" | must_have | 没有"优先""加分"等弱化词，是基本要求 |
| "专业不限，计算机/AI/设计相关背景优先" | nice_to_have | 明确写了"优先"，这不是硬门槛 |
| "有自己的 AI 产品作品（哪怕是个 side project）" | nice_to_have | 在"加分项"标题下 + 括号弱化 |
| "皮实…" | must_have | 虽然措辞随意但位于"我们希望你"而非"加分项"下 |

### 3.4 边界判断

| 决策 | 结论 | 理由 |
|------|------|------|
| location | "未知" | JD 全文中未提及工作地点 |
| info_sufficient | true | 有明确的职责 + 要求，可以分析 |
| 是否需要联网补全 | 否 | 字节跳动 + 豆包的背景已知，不需要额外搜索 |

## 四、极端场景对比（模拟演示解析器的鲁棒性）

### 场景 A：极简 JD（信息不足）

**输入**：
> "招 AI PM，负责产品规划，坐标北京，感兴趣私聊。"

**输出摘要**：
```json
{
  "company": "未知",
  "role": "AI PM",
  "location": "北京",
  "responsibilities": ["产品规划"],
  "requirements": [],
  "info_sufficient": false
}
```
> ⚠️ `info_sufficient=false`——没有可提取的技能要求，分析报告会标注"信息不足，仅供参考"。

### 场景 B：技术术语密集型 JD

**输入**（片段）：
> "熟悉 Transformer 架构、了解 RLHF 训练流程、有 CUDA 编程经验优先、掌握 vLLM/TGI 推理框架"

**解析后的 requirements**：
```json
[
  {"content": "熟悉 Transformer 架构", "type": "must_have", "category": "技能"},
  {"content": "了解 RLHF 训练流程", "type": "must_have", "category": "技能"},
  {"content": "有 CUDA 编程经验", "type": "nice_to_have", "category": "技能"},
  {"content": "掌握 vLLM/TGI 推理框架", "type": "must_have", "category": "技能"}
]
```
> 这些技术术语 LLM 不需要理解含义——只需识别句式："优先/加分/" → nice_to_have，其余 → must_have。
